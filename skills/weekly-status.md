# Weekly Status — Project Word

Two formats. Pick the one that matches the audience; don't blend them.

---

## Format A — Team / Eng audience

Async-first, direct, detail-heavy. Assume the reader wants enough to act without a follow-up meeting.

```
## Week of [date]

**State:** [one line — where the project stands right now]

**Done this week:**
- [item] — [file/artifact if applicable]
- [item]

**In progress:**
- [item] — [blocker or dependency, if any]

**Decisions made:**
- [decision] — [why]

**Open questions:**
- [question] — [who/what would answer it]

**Next week:**
- [item]
```

No bullet cap — completeness over brevity here.

---

## Format B — Leadership audience

One page. Status-first, no jargon. Assume the reader has 30 seconds.

```
## Project Word — [date]

**Status:** [On track / At risk / Blocked]

**Shipped:** [1–3 bullets max, plain language, no internal terms]

**Next:** [1–2 bullets]

**Blockers:** [only if real — omit section if none]
```

Max 3 bullets per section. If it doesn't fit in one page, cut detail, don't shrink the font.

---

## Pre-flight check (run before writing either format)

- Every "Done" or "Shipped" claim — point to a real artifact (file, working build, test result). Don't report something as done because it was discussed.
- Don't present a roleplay, mockup, or thought experiment as if it were user research or a real test.
- No audience named → write both formats.
