# CLAUDE.md — Betwixt

## Project

**Product:** Betwixt — a daily word-guessing game. Two compound words or common two-word phrases share an overlapping word — the second half of the first equals the first half of the second. The shared word is hidden as a blank; the player guesses it.

Example: *spotlight* + *lighthouse* → displayed as `spot _____ house` → answer: **light**.

**Problem:** No mobile/web game exists for this specific overlap-word puzzle format.

**Current phase:** Live and playable. Static site (`index.html`, `styles.css`, `script.js`, `puzzles.js`) implements the full spec — daily puzzle, 3-guess hint progression, streak via `localStorage`, exhausted-content end state — deployed at `https://tlava27.github.io/betwixt/`. 172 puzzles (compound words + phrases, merged). No real player has used it yet beyond this testing.

## Key Facts to Not Re-Derive

- **Stakeholders:** solo project — Trevor is the only stakeholder. No review or approval chain exists.
- **Puzzle mechanic is fixed:** the overlap must be a real shared substring between two compound words/common phrases (not a synonym or thematic link), and both leftover fragments must themselves be recognizable standalone words. `spotlight`/`lighthouse` → `light` is the canonical example. All puzzle text is lowercase.
- **Play format:** one puzzle per calendar day, same puzzle for every player. Rolls over at 12:00am US Eastern (`America/New_York`, DST-aware) — not UTC, not the player's local time.
- **Guess mechanic:** free-text input, 3 attempts. Guess 1: fixed-width blank, no hint. Guess 2: first letter of the answer revealed. Guess 3: blank switches to match the real letter count (full-length hint). Wrong guess is a plain miss — no "close"/"too short" feedback.
- **End states:** solve within 3 → shareable result text showing guess count. Fail all 3 → answer revealed, daily streak breaks.
- **Streak:** points-based, not +1/day. Solving on guess 1 = +5, guess 2 = +3, guess 3 = +1; the running point total *is* the streak. Tracked client-side only, `localStorage`, no accounts/backend. Resets to 0 on failing all 3 guesses *or* skipping a day entirely (day-index gap > 1 since last played) — those two reset conditions are unchanged from the original +1/day design, only the reward side changed.
- **Content:** 172 puzzles total, two mechanics merged into one list — not 50, that interview-stage target was revised multiple times since. **Compound-word track (days 0–78, 79 puzzles):** 56 from round 1 (curated, answers unique), 23 from round 2 (kept as-generated) — in `puzzle-candidates.md`. **Phrase track (days 79–171, 93 puzzles):** common idiomatic two-word phrases instead of fused compound words, same `{a, b, answer}` shape and identical rendering — no code changes needed to support it. Kept as-generated, no curation cut — in `puzzle-candidates-phrases.md`. **Answer words now repeat across the merged list** (15 answers exist in both tracks; the phrase track also repeats internally, e.g. "card" ×5) — the compound track's post-round-1 "one puzzle per answer" property no longer holds globally, by Trevor's explicit choice to merge as-is rather than dedupe first. Once a player exhausts all 172 days, show: "Thanks for testing the beta! More puzzles to be added soon." — never loop back to puzzle #1.
- **Platform:** static HTML/CSS/JS, no backend, no accounts. Hosted on GitHub Pages from `github.com/tlava27/betwixt` (moved 2026-09-25 from the original private `tlaverriere/Betwixt` — Pages can't publish from a private repo without a paid plan). Requires `.nojekyll` at root or GitHub Pages tries to run Jekyll over the markdown files.
- **Beta-testing day skip:** a "Skip to next day" button (`#skip-day-button`, always visible, outside the `#game` div so it survives every render state) adds to a `betwixt_debugDayOffset` localStorage value that's added to the real calendar-derived day index. Lets testers reach any puzzle without waiting for real days, and still correctly exercises the skip-breaks-streak logic. This is intentionally permanent for the beta phase, not scaffolding to remove later — revisit before a real public launch.
- **Betwixt wordmark:** the "i" in the `<h1>` title is deliberately styled upside-down and dark orange (`.flip-i` in `styles.css`) — a design choice, not a rendering bug.
- **Post-solve overlap reveal:** two translucent ovals (`.overlap-oval`) are drawn directly on top of the solved puzzle row in `renderSolved()` (`script.js`) — not a separate diagram below it, and not circles. Left oval spans `a`+answer, right spans answer+`b`, overlapping on the revealed letters. Their position/size is computed from `getBoundingClientRect()` on the real rendered text at solve time, not hardcoded pixel guesses — a hand-guessed version shipped with text poking outside the ovals before this was corrected. If this ever needs rebuilding, measure the real DOM, don't estimate font-metric widths by hand.
- **History modal:** a month-calendar popup (`#history-modal` in `index.html`, logic in `script.js`) auto-opens once, ~1 second after a solve or fail (`setTimeout(openHistoryModal, 1000)` in the submit handler — deliberate, so the player sees that day's result/reveal before the modal covers it) — triggered explicitly from the submit handler's solve/fail branches via `openHistoryModal()`, never from `render()`/`renderSolved()`/`renderFailed()` themselves, so reloading an already-completed day does *not* re-trigger it. Each day's cell: green = 5 points (solved guess 1), yellow = 3 points (guess 2), orange = 1 point (guess 3), solid red = failed puzzle (failed all 3), red ring/white fill = missed day (never played, day-index gap). Days before launch or after today render as plain neutral numbers, not "missed." Month nav is bounded to [launch month, today's month] using the *effective* day index (includes the beta day-skip offset) — skip-testing multiple simulated days moves the upper bound correctly. Date math reuses `dateStringToDayIndex`/`dayIndexToDateString` (UTC-string-anchored, DST-safe, same convention as the rest of the app) for day-index lookups, and separately uses plain local `Date` construction for calendar-grid layout (weekday/month arithmetic) — those are two different concerns, don't conflate them if this code changes. **The modal's setup and its reopen icon (`#history-open-button`, the 📅 next to the streak) are wired *before* the not-launched/exhausted early returns in `DOMContentLoaded`**, deliberately, so reopening history still works once a player has run out of puzzles. Single source of truth for a cell's outcome is `getDayStatus(cellDayIndex)` — both the visual grid and the shareable text read from it, so they can't drift apart. **Real bug hit and fixed while building this:** `.history-modal-overlay[hidden] { display: none; }` had to be added explicitly — a plain `.history-modal-overlay { display: flex; }` rule has the same CSS specificity as the browser's built-in `[hidden]` rule and loads after it, so the modal showed regardless of the `hidden` attribute until this was added. If any other `hidden`-toggled element in this app gets a `display` other than the default, it needs the same `[hidden]` override.
- **Share history:** a "Share history" button inside the modal copies a Wordle-style emoji grid of the *currently viewed* month (🟢🟡🟠🔴 for the four scored/failed states, ⭕ for missed day, ⬜ for no-data padding/future cells), built by `buildHistoryShareText()` off the same `getDayStatus()` used for rendering. Clipboard logic (`copyWithFeedback()`, `fallbackCopy()`) is now factored out and shared with the original per-puzzle "Share result" button rather than duplicated — both go through the same clipboard → `execCommand` → visible-manual-copy fallback chain. `⬜` rendered as a font-fallback glyph in the sandboxed test browser (unlike the colored-circle emoji, which rendered fine) — likely a font-coverage gap in that specific environment, not a data problem (the underlying character is correct), but unverified on real devices.
